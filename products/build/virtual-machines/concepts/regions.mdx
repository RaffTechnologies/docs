<sub>Updated November 9, 2026</sub>

A **region** is a geographic location where Raff operates compute, storage, and networking. The region you pick at VM creation determines where the VM physically lives, which IP ranges it can be assigned, and which VPCs it can join.

## Available regions

| Region | Code | Location |
|---|---|---|
| **US East** | `us-east` | Vint Hill, Virginia |
| **EU Central** | `eu-central` | Frankfurt, Germany |

Pick the region in the dashboard, or pass its code as `region` on every create call. The [List Regions](/api-reference/catalog/list-regions) endpoint returns the current regions and what each one sells in `products`, so your code never has to hard-code this list.

## What each region offers

| Product | US East | EU Central |
|---|---|---|
| Cost-Optimized servers (Linux) | Yes | Yes |
| General Purpose and CPU-Optimized servers | Yes | Not yet |
| Windows servers, Standard plans | Yes | Yes |
| Windows servers, Business plans | Yes | Not yet |
| Volumes, snapshots, and backups | Yes | Yes |
| VPC | Yes | Yes, without a router or VPN gateway |
| Site-to-Site VPN | Yes | Not yet |
| Kubernetes, Managed Databases, Apps, Functions, Object Storage | Yes | Not yet |

## What region scope means

A region is a hard boundary — resources from different regions cannot share networking or be moved between regions in place.

| Scope | Behavior |
|---|---|
| **VM location** | The VM's CPU, RAM, and disk physically live in the chosen region's datacenter |
| **VPC scope** | A VPC and every VM in it must share a region. You can't have one VPC spanning two regions |
| **Public IPs** | IPv4 / IPv6 addresses come from region-specific pools. A reserved IP can only attach to VMs in the same region it was reserved in |
| **Volumes** | A volume can only attach to VMs in its own region |
| **Object Storage** | Buckets are region-scoped; same-region traffic between VMs and Object Storage is free |
| **Snapshots** | Stored in the same region as the source VM |
| **Backups** | Stored separately from your server |

## Picking a region

- **Latency** — pick the region closest to your users: US East for North America, EU Central for Europe. Round-trip time to a region is the floor of how fast your service can respond
- **What you need** — check the table above: a region must sell everything your service uses
- **Data residency** — the region determines where your server disks and volumes are stored
- **Cross-region traffic** — same-region traffic between Raff resources is free; traffic between regions goes over the public internet and counts against egress

## Moving a server to a different region

You can't change a server's region, and a snapshot, backup, or custom image can't create a server in another region. The path:

1. **Create a new server** in the target region
2. **Copy your data** via SCP/SFTP/rsync
3. **Update DNS / load balancer / clients** to point at the new server
4. **Delete the source server** when the cutover is done — unused subscription time credits back to your balance

Keep the old VM running until the new one is verified — there's no auto-failover between regions.
